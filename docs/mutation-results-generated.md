Generated by `tools/gen_mutants.py`. Each row is one deliberate fault in a copy of the sources that
the generator wrote for `examples/amm-fee` (144 -> 32 -> 16 -> 3): the arbiter ingot (`tools/gen_arbiter.py`)
and, in the last rows, the model ingot (`tools/gen_fe.py`). Each mutant is built with `fe build`
and run against `evm/generated/GenArbiter*.t.sol` with `--fail-fast`, so the test named is the
first to fail, not the only one. The shipped two-layer arbiter's run is `docs/mutation-results.md`.

"Multi-layer" marks a fault a two-layer arbiter cannot have: the middle handler, whose input and
output are both hidden vectors, takes a hash, a leaf's layer number, a kernel, a range bound or a
vector from the wrong layer. Most of these still type-check; the compiler refuses only the kernel
swaps. A survivor is either given the test that kills it or argued equivalent at the end.

The suite under test is the shipped arbiter's (`evm/test/Arbiter*.t.sol`, `docs/fe-notes.md` M3.9)
with the sizes taken out: shapes, rows, biases, proofs and reference samples are read from a fixture
that `tools/gen_arbiter_fixtures_any.py` writes from the example's `out/model.json`, its reference
trace and its neuron tree, and the calldata is built from signatures derived from the spec. Its
oracle for what the network computes is `GModel` (`evm/generated/GenBase.sol`): the integer network
in plain Solidity over the fixture's rows, with the byte loop of `evm/test/SpecNeuron.sol`. It shares
no code with the Fe kernel, the generated model ingot or the generator, and
`test_oracle_reproduces_the_reference_samples` checks it against the committed reference trace (the
fixture writer also checks every sample against its own forward pass in Python). Run it with
`tools/gen_foundry.sh`; this file with `tools/gen_mutants.py`.

## Survivors and mutants that changed nothing

- `n2_reads_output_as_layer_1_type`: SURVIVED, and equivalent: no test can kill it. The mutant reads the middle layer's claimed value as `Hidden1::from_words(hidden2).get(j)` instead of `Hidden2::from_words(hidden2).get(j)`. In 144-32-16-3 both types are one packed word (`[u256; 1]`, 32 and 16 values), so it type-checks. The two reads differ in three ways, and none is reachable: `get` asserts `j < 32` instead of `j < 16`, but the handler has already refused `j >= HIDDEN2` with `NeuronOutOfRange` (which `n2_no_range_check` and `n2_range_of_layer_1` show is tested); `from_words` checks that bytes 16 to 31 are at most 127 instead of zero, but the vector has just been matched against the claim's `hidden2_hash`, and the claim stored that hash only after `Hidden2::well_formed` accepted it (`claim_hidden2_checked_as_32_values` is killed); and byte j of the word is the same byte for both types. So for every call that reaches the line, both versions return the same value and neither assertion fires (barring a keccak collision). The types separate layers only where the Fe signatures differ: the kernel swaps (`n2_uses_layer3_kernel`, `n3_uses_layer2_kernel`) are refused by the compiler because a hidden neuron returns an `i8` activation and the last layer an `i32` logit, but every handler takes its vectors as plain word arrays and `from_words` accepts any array of the right word count, so two layers whose vectors fit in the same number of words (here both in one) can be read as each other. That is what the rest of the multi-layer rows test, and the suite kills every such mutant that changes a value.
