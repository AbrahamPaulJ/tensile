Public API of `tensile` (`ingots/tensile/src/lib.fe`):

- `Activations<N, F>`: `N` int8 in 0..127 with `F` fractional bits, packed. `pack`, `from_words`, `words`, `get`, `==`.
- `Row<IN, FW>` (`Copy`), `Weights<OUT, IN, FW>`: packed int8 weights. `Row::pack`, `Row::from_words`, `Row::words`, `Weights::new`, `Weights::row`, `is_packed_from`.
- `Q<F>`: one int32 at scale `F`. `shifted<SHIFT>() -> Q<{F - SHIFT}>`, `clamped() -> i8`.
- `Bias<N, F>`, `Accumulators<N, F>`: int32 vectors. `requantise<SHIFT>() -> Activations<N, {F - SHIFT}>`, `argmax`, `values`, `==`.
- `neuron(row, x, bias: Q<{F + FW}>) -> Q<{F + FW}>` and `dense(weights, x, bias) -> Accumulators<OUT, {F + FW}>`, which is `neuron` once per row.
- `worst_case(weights, bias)`, `neuron_bound(row, bias)`, `I32_MAX`: the compile-time overflow proof.
- `Probe` (an effect trait) and `Blind`: observation of the hidden layers of a forward pass.
- `Packed<N>`, `word_count`: the storage, 32 int8 per `u256`.

## 2. Decisions that are not in `docs/spec.md`

- **Packing layout.** Value `i` is byte `i % 32` of word `i / 32`, most significant byte first,
  two's complement, unused bytes of the last word zero. The words in order are the byte encoding
  of spec section 7, and it is the layout of `core::bytes::PackedBytes`. `PackedBytes` itself
  could not be used: its field is private and the only constructor is `from_array`, which cannot
  be evaluated for 25,088 values (section 4). The spec should record this layout before
  milestone 3 hashes weights.
- **Activations are packed too.** One storage type for weights and activations, a kernel with no
  tail handling (the padding is zero on both sides), and a `[u256; 25]` is what a contract
  message should carry for an input (never `[i8; 784]`, see the spike, section 6).
- **Where the arithmetic is unchecked.** The sum of products is unchecked and safe for every
  input by a `where` clause, `dot_fits_i32(IN)` (`IN * 128 * 128 <= i32::MAX`, so `IN <= 131,071`).
  Adding the bias is ordinary checked arithmetic, one operation per neuron; `worst_case` proves at
  compile time that this check cannot fail for the generated model.
- **The bound is the exporter's:** `|b| + 127 * max(P, N)` per neuron (`ref/tensile_ref.py`), the
  layer value is the largest. The generated code asserts equality with `worst_case_abs_acc` from
  `model.json` (1,481,397 and 66,144) and `<= I32_MAX`.
- **CLI input checking.** A byte above 127, or input ending inside a sample, ends the run with
  exit status 2. The spec only says inputs are 0..127.

Each has the exact message and, where it is a defect or a limit, a file under `tests/defects/`
(`fe check <file>` reproduces it).

|---|---|---|---|

Things that simply worked, and are worth knowing they work: `Q<{ F + FW }>` as a PARAMETER type
(the bias), `{ F - SHIFT }` in a return type, `where` with a const fn call (`where dot_fits_i32(IN)`),
struct fields typed by a const fn (`[u256; word_count(N)]`), `pub(ingot)` fields, type aliases with
const arguments, an effect whose trait method is generic over const parameters (`Probe::hidden<N, F>`),
providing a struct field as an effect (`with (Write = self.out)`), `main(argc, argv)` with
`std::native::Args`, generic enums (`Chunk<N>`), and test doubles for `Read` and `Write`.
The `cli` ingot's tests also pass on the EVM backend.

## 4. What fits in the compile-time evaluator

The limit is 1,000,000 steps per evaluation (spike, section 3). Measured with the real library
through the real generator (`fe check` on a one-layer model, 784 inputs per row):

| Computation | Largest that fits | Smallest that fails |
|---|---|---|
| `worst_case` (the overflow proof, 32 weights per step) | 192 x 784 = 150,528 weights | 256 x 784 = 200,704 |
| The same bound visiting weights one at a time (spike-style loop over plain arrays) | 8 x 784 = 6,272 | 16 x 784 = 12,544 |
| `is_packed_from` (pack the int8 matrix and compare) | 12 x 784 = 9,408 | 16 x 784 = 12,544 |

Consequences:

- The proof for the 784 x 32 layer (25,088 weights) runs in ONE `static_assert`, because
  `neuron_bound` works on whole packed words (`ingots/tensile/src/bound.fe`). Visiting weights one
  by one fails with `error[3-0026]: const evaluation exceeded the step limit`.
- Per-row constants do not rescue a too-large evaluation. With the one-weight-at-a-time bound and
  32 constants `R0..R31` (one row of 784 each): every constant evaluates on its own, and
  `max_of([R0, R1, R2, R3])` passes, but `max_of` over 16 or 32 of them fails with the same
  error. Constants referenced from one evaluation are evaluated again inside it, and their steps
  add up. Only separate `static_assert`s, one per row, stay under the limit, and those cannot
  express "the largest equals the recorded value".
- Compile-time packing is checked for layer 2 (320 weights): the generated `layer2.fe` holds both
  the int8 matrix and the packed literal, and `static_assert(WEIGHTS.is_packed_from(INT8))`.
  Layer 1 (25,088 weights) is over the limit, so it has the packed literal only
  (`PACK_CHECK_MAX_WEIGHTS = 8192` in `tools/gen_fe.py`). Its packing is covered by the reference
  tests instead.
- A failed `assert!` inside a `const fn` evaluated for a constant is a compile error
  (`assertion failed in const context`), so constructors can validate constants for free.

## 5. Native backend performance

In the real CLI, CPU time of layer 1 (784 x 32) for 1,000 samples at `-O 1`, measured with
`std::native::cpu_clock_ticks()` around the call in a scratch copy of the CLI:

| Kernel formulation | Layer 1, 1,000 samples |
|---|---|
| Four 64-bit limbs per word, each lane `(limb >> s).downcast_truncate()` to `i8`, loops | 2.2 s |
| The same with the eight lanes written out | 1.7 s |
| Limbs as `i64`, lane = `((a << skip) >> 56) * ((b << skip) >> 56)`, written out (milestone 1 form, replaced in milestone 2: M2.7) | 0.25 to 0.39 s |

In isolation (a standalone loop over 256 million products, the work of 10,000 samples, `-O 1`,
taken earlier in the session when the machine was less loaded):

| Formulation | 256 million products |
|---|---|
| Lanes read from the `u256` word with 256-bit shifts (`word >> 248`, `word << 8`) | 19.6 s |
| Four 64-bit limbs per word, looped lanes | 6.8 s |
| 64-bit limbs, lanes written out | 3.8 s |
| Plain `[i8; 800]` arrays, no packing at all | 3.7 s |

- 256-bit shifts and multiplications are slow natively. Do the inner work on 64-bit values.
- `downcast_truncate` between narrow integers (`u64` to `i8`) stayed an out-of-line call of about
  580 bytes in the generic kernel. Removing it from the inner loop was worth a factor of 4.4.
  Sign-extend with a shift pair instead.
- `isize` is not faster than `i32` natively (15.6 s against 6.8 s on the same loop).
- The packed kernel with written-out lanes is as fast as plain int8 arrays (3.8 s against 3.7 s),
  so packing costs nothing natively once the 256-bit operations are out of the inner loop.
- Packing 784 values per sample with a variable shift per value (`word |= byte << shift`) cost
  0.43 s per 1,000 samples, more than inference. Shifting the word by a constant 8 per value
  costs 0.10 s (`Packed::pack`).
- Reading 784 bytes per sample through `read_char` costs about 0.12 s per 1,000 samples.

End to end with the milestone 1 kernel (`tools/diff_native.sh`): 10,000 samples in 13.2 s at
`-O 0`, 4.4 s at `-O 1`, 4.5 s at `-O 2`. Binary: 279,032 bytes at `-O 0`, 152,024 at `-O 1` and
`-O 2`. The kernel was replaced in milestone 2 by the `u32` limbs form, measured on both targets:
sections M2.3 to M2.7 below (the classes-only run at `-O 1` went from 2.69 s to 4.47 s, EVM gas
per multiply-add from 143.9 to 70.9).

## M2.1 State of the work

Done and tested (tensile 20 tests, model 6 tests, EVM and native backends):

- `ingots/tensile/src/dot.fe` is new: the inner dot product moved out of `dense.fe`, so a kernel

- `tools/gen_fe.py` emits, per layer: `neuron(row, x, bias)` (typed, `tensile::neuron` plus the
  layer's requantisation), `neuron_from_words(row, x, bias)` (packed words, validated by
  `Row::from_words` and `Activations::from_words`), `row(j)`, `bias(j)`. `reference.fe` now has
  public constants (`X0`, `HIDDEN1_0`, `LOGITS0`, `CLASS0`, ...) and a neuron-by-neuron test per
  sample.

## M2.2 Kernel forms: plan (no measurements yet)

Candidates, each a replacement `dot.fe`, to be measured for EVM gas per multiply-add (784-input

1. `i64-lanes`: the milestone 1 form (64-bit limbs, lane = shift up, arithmetic shift down).
2. `i256-loop`: 256-bit accumulator, bytes read with shifts in a loop (the spike's form).
3. `i256-signext`: bytes truncated to `i8` and widened (SIGNEXTEND on the EVM).

5. `usize-limbs`: limbs held in `usize` (256-bit on the EVM, 64-bit natively), weights read as

Quick measurements (gas() inside, as in M2.3, and native time; no anvil run). The row name is the
file in `tests/kernel_forms/` where one is kept.

| Form | gas() per multiply-add | native | Kept as |
|---|---|---|---|

| the same, sum of x by a SWAR sum per limb | 98.7 | 2.07 s | (not kept) |
| the same, sum of x per word (`lane_sum` from `bound.fe`) | 89.6 | 2.62 s | `u64_limbs.fe` |

| the two above with `usize` instead of `u256` | 75.4, 61.1 | 5.99 s, 17.10 s | (not kept) |
| `i64` limbs, unsigned lanes `(a >> s) & 0xff`, all in `i64` | 121.5 | 3.38 s | (not kept) |
| `i64` lanes, accumulated in `i256` | 119.5 | 6.54 s | (not kept) |
| `i64` milestone 1 form with unsigned activation lanes | 133.3 | 2.70 s | (not kept) |
| `u32` limbs (8 per word), 4 lanes each, `dot4` in `u32`, accumulated in `u64` per limb | 72.7 | 4.45 s | (not kept) |
| `u32` limbs, accumulated in `u256` per limb | 69.2 | 5.34 s | `u32_acc256.fe` |
| `u32` limbs, the 32 products of a word summed in `u32`, one `u64` add per word | 70.9 | 4.49 s | KEPT: `ingots/tensile/src/dot.fe` |

What the EVM lowering of narrow integers costs (from `cast disassemble` of a two-limb test
contract, `tests/defects/` has no entry because it is not a defect, only a cost):

- After every `u64` multiplication or addition the result is masked with
  `PUSH0 NOT PUSH1 0xc0 SHR AND`, 14 gas. A `u32` mask is `PUSH4 .. AND`, 6 gas. An `i64` result
  is sign-extended, 8 gas, but `>>` on `i64` is more expensive than on `u64`. A `u256` operation
  has no mask. `>>` and `& 0xff` on narrow unsigned values are not masked.
- `usize` behaves like `u256` natively for speed (identical times to `u256` in two forms, 15x
  slower than `u64` on the same lanes in M2.4), although the language says it is 64-bit natively.
  `tests/defects/usize_native_speed.fe` is the minimal example: the same 256-million-step loop
  takes 17.8 s in `usize` and 0.36 s in `u64` (50x).

Decision: the `u32` limbs form is kept for both targets. Against the best form for each target
alone it costs 30.8% more gas than the best EVM-only form (70.9 against 54.2 per multiply-add,
inside the EVM, validation included) and 1.66x the time of the best native form (4.49 s against
2.70 s for 10,000 samples). The limits in the brief were about 30% and 2x; nothing measured was
closer on both at once (`u32` accumulated in `u256`: 27.7% and 1.98x, both numbers within the
noise of the other, and the native time varies more between runs). One form, one source: the
claim of the project holds without a per-target kernel.

## M3.2 Decisions and deviations from `docs/spec-dispute.md`

- **Two neuron-challenge handlers, not one.** The spec's `challenge_neuron(claim, l, j, input,
  output, row, bias, proof)` cannot be typed once: the input of layer 1 is `[u256; 25]` and its
  output `[u256; 1]`, the input of layer 2 is `[u256; 1]` and its output `[i32; 10]`. The layer is
  in the selector: `challengeNeuron1(...)` and `challengeNeuron2(...)`. That is the typed layers
  doing their job, not a limitation; the spec should say "one handler per layer".
- **The root, the bond and the window are constructor arguments** (`init(model_root, bond,
  window)`), not constants. The deployer commits the root (spec section 7); the Fe tests and the
  gas script pass `model::MODEL_ROOT`. A window of zero makes a claim finalisable at once, which is
  how the contract tests reach `Final` without time travel (M3.3, finding 22).
- **The claim event carries dynamic arrays.** `Claimed.x0`, `.hidden` and `.logits` are
  `uint256[]`, `uint256[]`, `int32[]` of the fixed lengths 25, 1 and 10, because an event field
  cannot be a fixed-size array in Fe 26.5.1 (`tests/defects/event_fixed_array.fe`). The message
  fields are fixed-size arrays as the spec says.
- **The logits hash is `keccak256(abi.encode(int32[10]))`**, 32 bytes per element sign-extended,
  as `docs/spec.md` section 7 says since milestone 2. The word hashes are `keccak256` of the packed
  words in order (`keccak256(abi.encodePacked(x0))` for a `uint256[25]` in Solidity).
- **Class range.** `class` is a `uint8` and must be below 10 (`ClassOutOfRange`); a neuron index at
  or above the layer's size is `NeuronOutOfRange`. The spec names only the class bound.
- **A row with -128** is accepted, as in milestone 2: the Merkle proof fixes the row to an exported
  one, so the open question of M2.10 does not arise in the arbiter.
- **Order of checks in a challenge.** Hashes, then the proof, then the recomputation, then the
  lifecycle rule (`dispute::step`) with the fraud bit. A challenge of a closed claim therefore pays
  for the recomputation before it learns `ClaimNotOpen`; the rule needs the fraud bit, and checking
  the status twice would duplicate the rule. Both orders revert, so nothing observable changes.
- **Claims are numbered from 0** (`claimCount()` is the next number). `result(id)` reverts with
  `NotFinal` for anything but a `Final` claim, with `UnknownClaim` for a number not yet used.
- **Reentrancy.** `withdraw` zeroes the credit before the transfer and forwards all gas; a
  re-entrant `withdraw` finds nothing, and a re-entrant `claim` or challenge only adds or ends a
  claim under the same rules, so the balance invariant (P1) holds through the callback. No mutex.
- **The auditor's input** is binary, one claim after another: 784 input bytes, 32 hidden bytes
  (each 0..127), 10 logits as big-endian two's complement int32, one class byte. It prints one
  line per claim. A byte above 127, a class of 10 or more, or input ending inside a claim stops
  the run with exit status 2 (the convention of `cli` for malformed input); such a claim would be
  rejected by `claim` anyway, so the auditor never names a check for it.
- **Spec changes to recommend:** section 3 should say the class is a `uint8` below `OUT_last`;
  section 4 should list one neuron handler per layer and the dynamic-array event; section 10's
  projection (claim 150,000, layer-1 challenge 250,000) should be replaced by M3.6 (246,141 and
  156,380: the claim is dearer because of seven fresh storage slots, the challenge cheaper because
  the kernel costs 71 gas per multiply-add since milestone 2).

Build: `fe build --out-dir <out> --ingot onchain .` writes `Arbiter.bin` (creation code),
`Arbiter.runtime.bin` and `Arbiter.abi.json`. Deploy with the constructor arguments appended to the

Calls (Solidity signatures; `uint256[25]` and `uint256[1]` are packed words, `docs/spec.md` section
7; every revert is a custom error named here):

| Call | Effects used | What it does |
|---|---|---|
| `claim(uint256[25] x0, uint256[1] hidden, int32[10] logits, uint8 class) payable returns (uint256 id)` | `ctx`, storage, `log` | needs `msg.value >= bond()` (`BondTooSmall(sent, required)`); rejects a byte above 127 or non-zero padding (`MalformedInput()`, `MalformedHidden()`) and `class >= 10` (`ClassOutOfRange(class)`); stores claimant, class, status 1, bond = `msg.value`, deadline = now + window and the three hashes; emits `Claimed`; returns the id (0, 1, ...) |
| `challengeNeuron1(uint256 id, uint256 j, uint256[25] x0, uint256[1] hidden, uint256[25] row, int32 bias, bytes32[] proof)` | `ctx`, storage, `log` | `UnknownClaim(id)`; `j < 32` (`NeuronOutOfRange(j)`); `x0` and `hidden` must hash to the commitments (`InputMismatch()`, `OutputMismatch()`); `leaf(1, j, bias, row)` must verify against the root (`NotCommitted()`); recomputes the neuron; then the rule: `ClaimNotOpen(id)`, `TooLate(deadline)`, `NoFraud()`, or status 2, the bond credited to the caller and `NeuronSlashed(id, caller, 1, j)` |
| `challengeNeuron2(uint256 id, uint256 j, uint256[1] hidden, int32[10] logits, uint256[1] row, int32 bias, bytes32[] proof)` | same | the same for layer 2 (`j < 10`); the recomputed logit is compared with `logits[j]` |

| `finalize(uint256 id)` | `ctx`, storage, `log` | `UnknownClaim`, `ClaimNotOpen`, `TooEarly(deadline)`, or status 3, the bond credited to the claimant, `Finalized(id, class)` |
| `withdraw() returns (uint256)` | `ctx`, storage, `log`, **`mut call`** | pays the caller's credit to the caller with all remaining gas; `NothingToWithdraw()`; the credit is zeroed before the transfer and `TransferFailed()` reverts both; the only handler that sends ETH |
| `result(uint256 id) returns (uint8)` | storage | the class of a `Final` claim; `NotFinal(id)` otherwise |
| `claimCount() returns (uint256)`; `claimInfo(uint256) returns (address claimant, uint256 bond, uint256 deadline, uint8 class, uint8 status)`; `claimHashes(uint256) returns (uint256 x0Hash, uint256 hiddenHash, uint256 logitsHash)`; `creditOf(address) returns (uint256)`; `modelRoot()`, `bond()`, `window()` (`uint256`) | storage | views; `UnknownClaim` for an unused id |

Hashes: `x0Hash = keccak256(abi.encodePacked(x0))` (the 25 words in order), `hiddenHash` likewise over
one word, `logitsHash = keccak256(abi.encode(logits))` for an `int32[10]`. Status codes: 1 open,
2 slashed, 3 final (0: no claim). Events:
`Claimed(uint256 indexed id, address indexed claimant, uint256[] x0, uint256[] hidden, int32[] logits, uint8 class, uint256 bond, uint256 deadline)`,
`NeuronSlashed(uint256 indexed id, address indexed challenger, uint256 layer, uint256 neuron)`,
`ClassSlashed(uint256 indexed id, address indexed challenger)`, `Finalized(uint256 indexed id, uint8 class)`,
`Withdrawn(address indexed account, uint256 amount)`.

Proofs and rows: `build/tree.json` lists, per leaf, `layer`, `neuron`, `leaf` and `proof`
(`bytes32[]`, the leaf's sibling first); `python3 tools/claim_args.py proof L J` prints the row
words, the bias and the proof in `cast` syntax; `python3 tools/claim_args.py claim [--sample N]
[--mutate hidden:J|logit:J|class]` prints the four `claim` arguments of an honest or once-mutated
claim. The leaf is `keccak256(abi.encodePacked("tensile.neuron.v0", uint256(l), uint256(j),
int256(bias), row))` with `row` the `uint256[25]` or `uint256[1]` words (32 bytes each). The honest
claim for a sample is the `cli trace` output or `trace.jsonl`; `cli audit` names the challenge to
send (`neuron l j expected claimed` is `challengeNeuronL(id, j, ..)`, `class expected claimed` is
`challengeClass`).

The arbiter receives ETH only through `claim`; it has no fallback. Properties P1 to P6 map to:
P1 `address(arbiter).balance == sum of bonds of claims with status 1 + sum of creditOf` (a credit
is added when a claim leaves status 1 and removed by `withdraw`); P2 every challenge of an honest
claim reverts with `NoFraud`; P3 a mutation of hidden `j` is slashed by `challengeNeuron1(.., j, ..)`,
of logit `j` by `challengeNeuron2(.., j, ..)`, of the class by `challengeClass`; P4 status only
moves 1 -> 2 or 1 -> 3, and `creditOf` grows by exactly one bond per move; P5 `vm.warp` to
`deadline - 1` (challenge allowed, finalize `TooEarly`) and `deadline` (challenge `TooLate`,
finalize allowed); P6 the `Malformed*`, `ClassOutOfRange` and `BondTooSmall` reverts.

**Invariant campaign.** A handler drives 8 actions (honest and false claims, malformed claims, correct,

root, one extra wei) prove the invariant can fail. The campaign writes what it did after each run and

## M4.3 What the abstractions cost

`tools/m4_numbers.sh`, table in `docs/numbers.md` section 2. Removing `Packed`, `Row`, `Activations` and `Q`

the gap to the best Solidity comes from limb masking (M2.6) and from the storage layout (below).

## The WebAssembly target (2026-11-07, master `89d07b9`)

Built with `cargo build --release -p fe --features "wasm cranelift"` (7.6 min on the i5-13420H; the build
also needs the tree-sitter CLI, from `npm ci` in `crates/tree-sitter-fe`). What the kernel needed:

- **No change to the kernel.** `ingots/tensile` and `ingots/model` compile for wasm unchanged, `u256`
  words and all: the target lowers 256-bit arithmetic inside functions, and only the export boundary is
  limited to `bool` and integers of at most 64 bits. All 26 unit tests pass on `--backend wasm`.
- **Standalone files only.** `fe build --backend wasm` refuses an ingot, so `tools/gen_wasm.py` wraps each
  source file in an inline `mod` and rewrites `ingot::` and dependency paths. Inner doc comments (`//!`)
  are not allowed inside an inline `mod`, so they become `//`.
- **Input through an import.** `HostText` gives an address and a length but no byte access from safe Fe,
  so the 784 pixels come through `extern { fn pixel(_ i: u32) -> u32 }`, called in `unsafe { }`.
- **Casts.** A lossless `as` must be lossless on every target, and `usize` is 32 bits here: `u32 as usize`
  is fine, `usize as u32` and `i8 as u32` are refused (`.downcast_truncate()`, or `as i32` for an `i8`).
- **Size and speed.** 37,471 bytes at `-O 1` (46,346 at `-O 0`, 37,304 at `-O 2`); 380 microseconds per
  image in Node 22, against about 260 ms for the same forward pass on the in-page EVM. Two builds give
  identical bytes.
- Three of our 26.5.1 defects are fixed on this commit (stack overflow, compile time, native byte order);
  `docs/upstream-reports.md` has the table and the issues filed for the rest.
