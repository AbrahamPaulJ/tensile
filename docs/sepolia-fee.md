# The fee-tier example, live on Sepolia

Generated by `tools/sepolia_fee_page.py` from `deploy/sepolia-fee.jsonl` (every transaction the
deployment and the hand-run keeper cycles sent), `deploy/sepolia-fee-budget.json` (the budget read
before deploying) and `deploy/sepolia-fee-running.json` (the balance read since, by `tools/fee_budget.mjs`).
Nothing here is typed by hand. The status page is
[abrahampaulj.github.io/tensile/fee-live/](https://abrahampaulj.github.io/tensile/fee-live/).

## What runs

- **The keeper** (`tools/fee_keeper.mjs`, every 10 minutes from `.github/workflows/fee-keeper.yml`)
  reads the tick of the mainnet Uniswap v3 USDC/WETH 0.05% pool at every 50th mainnet block, from
  two public mainnet nodes that must agree, and writes it to `TickRelay` on Sepolia, which hands it
  to `FeeOracle.observe()` in the same call. Every 6 moves (one hour) it runs the 144-32-16-3 network
  on the oracle's newest window and posts the answer to the `Arbiter` with a bond. After the dispute
  window it finalises the claim and applies it to `FeeOracle`, whose `fee()` then returns the tier's fee.
- **The watcher** is in the same keeper run (it challenges any false claim it finds, anyone's) and,
  without a key, in `demo/test/tensile-fee-live.mjs` (hourly in the same workflow) and in the status
  page, which re-reads the newest 288 relayed ticks (a day) from mainnet and re-runs every claim in the browser.

## Late, skipped and repeated runs

GitHub's schedule is coarse: runs start late and some are skipped. The keeper keeps no state of its own;
each run reads the relay, the oracle and the arbiter, and does what is due:

- **late or skipped**: the next run relays every grid block it missed up to mainnet's `safe` head (at most
  72 ticks, six hours, a run; a longer gap takes more runs), each tick read at its own mainnet block, so
  the moves stay 50 mainnet blocks apart. It claims only the newest window that ends on a multiple of 6
  moves; windows passed over while it was not running are not claimed afterwards. A claim whose window
  has passed is finalised on the next run, however late;
- **repeated**: a run right after another finds nothing due and sends nothing (the anvil test checks it);
- **overlapping**: the workflow's concurrency group runs one keeper job at a time, and a run that sees a
  pending transaction of its account sends nothing;
- **never ahead of mainnet**: the relay accepts only the next block of its grid, and the keeper relays
  only blocks at or below the smallest `safe` head the public mainnet nodes report (at least two must
  answer), each tick read from two nodes that must agree.

The relay's grid is its clock, not Sepolia's blocks, so a catch-up cannot invent an observation: the tick
of every grid block is mainnet's, and anyone can re-read it (below).

## Trust assumption: the relay

Sepolia has no pool that trades at mainnet prices. On Sepolia `FeeOracle` therefore reads
`TickRelay`, and **the relay holds whatever tick the keeper wrote**: nothing on Sepolia can check it
against mainnet. What makes the trust checkable:

- the relay accepts ticks only on one grid of mainnet blocks: tick `n` is of block `firstBlock() + 50 n`,
  with no gap and no repeat, the first block a multiple of 50 (the grid of `examples/amm-fee/data/ticks.csv`);
- every tick is emitted with its mainnet block (`Relayed(number, block, tick, moves)`), so anyone can read
  the pool's `slot0()` at that block and compare: the watcher does it for every tick, every hour, and so
  does the status page on every visit;
- the relay answers `slot0()` only inside its own `relay` call, which calls `observe()` once per tick, so
  the oracle cannot store a tick twice or one that was not relayed.

On mainnet there would be no relay: the oracle reads the pool itself (`examples/amm-fee/fork_check.sh`
did that once on a fork). The other trust assumptions are the example's own: one honest watcher awake
inside every dispute window, and a spot tick as input (one trade in the observed block moves it).

**Sepolia-specific deployment choice.** `FeeOracle` is deployed with an interval of 0 blocks: its
clock is the relay's grid of mainnet blocks, not Sepolia's blocks. A keeper run that is late, or a
skipped run, is caught up by the next run, which relays the missed ticks, each read at its own mainnet
block, so the moves stay 50 mainnet blocks apart as in the training data. That catch-up is visible on
chain: the Sepolia block of a `Relayed` event comes later after its mainnet block than usual. The first
window was filled the same way at the start (below).

## Check it yourself

```
bash tools/check_deployed_fee.sh                  # the bytecode at each address is fe build's
node demo/test/tensile-fee-live.mjs              # the newest 288 relayed ticks against mainnet (RECHECK=0: all, needs an archive node), every claim re-run
cast call --rpc-url https://ethereum-sepolia-rpc.publicnode.com 0xdd922018de3ace1185ccb892b0ed911b4249c41d "fee()(uint32)"
cast call --rpc-url https://ethereum-sepolia-rpc.publicnode.com 0xee5271bbade35b6223f0abc3180de870a716d8bf "latest()(uint256,int32)"
cast call --rpc-url https://eth.drpc.org --block <that block> 0x88e6A0c2dDD26FEEb64F039a2c41296FcB3f5640 "slot0()(uint160,int24,uint16,uint16,uint16,uint8,bool)"
```

The last two print the relay's newest tick with its mainnet block, and the pool's tick at that block on
mainnet: they must be equal.

## Run the keeper by hand

```
cd demo && npm ci && cd ..
SEPOLIA_KEY_FILE=<a file with a line private_key=0x...> node tools/fee_keeper.mjs --dry-run   # estimates, sends nothing
SEPOLIA_KEY_FILE=<a file with a line private_key=0x...> node tools/fee_keeper.mjs --record    # one run, appended to the record
node tools/fee_budget.mjs && python3 tools/sepolia_fee_page.py                                 # this page
bash tools/fee_live_anvil.sh                                                                    # the whole system on anvil
```

Only the relay's keeper (the deployer) can relay; anyone can claim, challenge and finalise. The
scheduled workflow (`.github/workflows/fee-keeper.yml`) runs the same script with the key in the
repository secret `SEPOLIA_KEEPER_KEY`, without `--record`.
