## 1. The task and the model

The task, the data, the labels, the thresholds and the test windows are those of `examples/amm-fee`
(`dataset.py` here loads that example's `dataset.py` and changes only the input length). Only the input is
longer: the last 288 moves (48 hours) instead of 144 (24 hours).

## 3. Gas: the whole run does not fit a transaction; a dispute is one filter on one window

**The whole forward pass cannot run in one Osaka transaction.** `tools/network_gas.sh` deployed the
generated `Network` (every layer in one contract, 70,261 bytes) on anvil at the Osaka hardfork and asked for
`classify` of test sample 0:

```
cast estimate:                         17966815
cast send, 30,000,000 gas limit:       {"schema_version":1,"success":false,"data":null,"errors":[{"level":"error","code":"cast.error","message":"server returned an error response: error code -32000: intrinsic gas too high -- tx.gas_limit > resolved tx gas limit cap"}],"warnings":[]}
```

It then deployed the same bytecode on a fresh anvil at Prague (no per-transaction cap, block gas limit
1,000,000,000), checked `classify` on 20 samples against `pred.bin` and `trace` of sample 0 against
`trace.jsonl` (every hidden value and logit), and mined `classify`: **17,966,815 gas, 1.07 times the 16,777,216 gas an
Osaka transaction may use.**

**Nor can it be deployed.** The `Network` contract is 70,261 bytes of runtime code, 2.86 times the 24,576 bytes
a contract may have (EIP-170), and its 70,282 bytes of init code exceed the 49,152 that EIP-3860 allows. It
was measured on anvil started with `--disable-code-size-limit`, deployed through a raw `eth_sendTransaction`.

**Unflattering, and a projection, not a measurement:** the dense kernel's whole run of 784 -> 128 -> 64 -> 10
costs 8,219,318 gas for 109,184 multiply-accumulates, 75.3 gas each. At that rate this model's 133,856 would cost about
10,076,614 gas, 60.1% of the cap. The generated convolution costs 134.2 gas per multiply-accumulate instead: layer 1 is
4,496 separate `neuron` calls on windows of 8 values, so the fixed cost of a call dominates. "Over the cap"
and "over the size limit" are facts about this generated contract, not bounds on every implementation of
this model; a contract written for gas might fit. The dispute does not depend on either.

### What the numbers show

- **A wrong value anywhere in this network is disputed for 62,940 to 110,306 gas** (later challenges), 0.4% to 0.6%
  of the whole run that one Osaka transaction cannot hold. A filter challenge costs 91,832 to 107,674 gas. For scale, the dense fee model's neuron
  challenges cost 66,995 (`challengeNeuron3 (16 inputs)`, the smallest) to 82,591 (`challengeNeuron1 (144 inputs)`), so the dearest filter challenge here is 1.61
  times the smallest dense one: a dispute stays the size of one neuron while the whole run grows 38.5 times
  between the two fee models.
- **The binding was chosen by these rows.** With the flat binding the dearest later filter challenge,
  `challengeFilter2 (4 x 16 window)`, costs 208,130 gas: it carries the layer's whole input and output as calldata, and is priced by
  the calldata floor of EIP-7623 ("floor" in `runs/arbiter-gas-flat.json`). With the word tree it costs
  107,674. The flat claim is cheaper (520,243 gas against 617,131: the word tree computes a Merkle root of every
  vector on-chain), so the flat binding is cheaper on the honest path by 96,888 gas, and the word tree is
  cheaper per dispute by up to 100,456. What decides it: **the flat `Arbiter` is 27,394 deployed bytes, 2,818 bytes over the
  24,576-byte limit of EIP-170, and could not be deployed** (it was measured on anvil with
  `--disable-code-size-limit`); the word-tree `Arbiter` is 22,565. A dispute that stays small however
  long the sequence grows is also what the scheme is for. `tools/gen_arbiter.py --binding flat` gives the other.
- **Unflattering: the claim is the dear part.** The honest path costs 672,404 gas, 2.31 times the dense fee
  model's, because the claim's calldata holds every hidden vector (6,372 bytes of calldata) and the claim
  hashes them into word trees. It is still 3.7% of a whole run.
- **And the model is no better than the dense one** (section 2). What this example shows is the
  mechanism: a network whose full evaluation does not fit a transaction is still settled by one
  transaction that re-runs 8 to 272 multiplications, against the whole run's 133,856.
