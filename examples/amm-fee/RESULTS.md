A "later" challenge is the same challenge when the challenger's credit and the contract's `burned`
total are already non-zero; the first slash of a run pays 34,200 gas more for those two slots.

### What the numbers show

- **Unflattering: a model this small does not need the dispute.** The honest path costs 290,511 gas, 62.3% of
  the 466,408 that running the whole network on-chain costs. The consumer must also check the claim's input
  (`apply`, 113,934 gas after the first, section 4), so one decision by the claim route costs 404,445 gas: 61,963 less than the whole run
  (which would still need a transaction of its own to store the fee; that was not measured). A claim has
  a fixed cost (a record of eight storage slots, the event, the bond) that a network of 5,219 parameters
  hardly outweighs, and the claim route adds a bond, a window and a watcher.
- **The saving comes with size.** The same honest path is 15.6% of a whole run for 25,450 parameters and 4.0%
  for 109,386, because the claim grows with the layer widths (239,460, 246,113 and 274,284 gas) while the whole run grows
  with the number of weights (466,408, 1,896,043 and 8,219,318 gas). A fee model with a longer history or wider layers
  moves along that line; this example does not claim such a model would predict better.
- **A dispute is still one neuron.** The dearest challenge here costs 116,791 gas, 25.0% of the whole run.
  The cheapest, `challengeClass`, costs 58,503: below a few hundred inputs the fixed part dominates.

## 4. The consumer: `FeeOracle` on the real ticks of test sample 11 (`oracle_check.sh`)

A test pool answered `slot0()` with the 145 real ticks behind test sample 11 (the first whose reference tier
is not the middle one, so that the fee leaves its default of 3,000), one every 50 mined
blocks. The packed input the contract built from them equals that sample in `out/inputs.bin`; the honest
claim about it was finalised after its window and applied: tier 0, `fee()` 500 (hundredths of a basis
point). After one more observation the next sample's window, which starts inside a stored word, also
equalled `out/inputs.bin`, and its claim set tier 1, `fee()` 3,000. An observation inside the interval, an
open claim, a second `apply` of one window and a claim applied to the wrong window were each refused.

| Call | Gas used |
|---|---|
| `observe()`, the first (stores the starting tick only) | 95,554 |
| `observe()`, the 145 after it: median, lowest, highest | 51,685, 46,064, 85,864 |
| `apply(id, end)`, the first: rebuild and hash the window, two reads of the arbiter, three fresh slots | 167,967 |
| `apply(id, end)`, the next one | 113,934 |
| `fee()` (estimate of a transaction; a hook would pay less, as an internal call) | 29,804 |

One fee decision every 24 intervals therefore costs about 1,240,440 gas of observations (24 times the median),
290,511 for the honest claim and 113,934 to apply it: 1,644,885 in all. The observations are 75.4% of that, and they
would cost the same if the network were run on-chain directly. Unflattering: `observe()` is written to
be read, not to be cheap (a call to the pool, five storage writes and an event each time); what a
hook that already holds the tick would pay was not measured. These sums are arithmetic on the rows
above, not separate measurements.
