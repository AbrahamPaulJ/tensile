# Address risk as a forest: gradient-boosted trees a contract can act on

The model family practitioners actually use for tabular risk scores, through Tensile end to end:
300 gradient-boosted trees of depth 6, on exactly the data, split, feature thresholds and test rows
of `examples/address-risk` (a scam-address score from 14 on-chain features of an Ethereum account).
The kernel is a new ingot, `ingots/trees`; the arithmetic, the commitment, the two challenges and
the soundness argument are `docs/spec-trees.md`.

**The user story.** The same as the dense example: a pool wants to refuse accounts that behave like
known scam addresses, by a published model anyone can re-run. An operator computes 14 features,
runs the forest, and posts the answer with a bond, committing to the output of every tree; anyone
who re-runs the forest and gets another answer proves it with one transaction that **re-walks one
tree** (6 comparisons and a Merkle proof) or re-adds the committed outputs. `RiskGate`
(`ingots/consumer`) reads the finalised answer and lets only cleared accounts in.

**What was measured, in one paragraph** (all of it from `RESULTS.md`, which `check.sh` generates).
On the same 7,054 held-out accounts the integer forest is right on 91.22%, where the dense network
is right on 89.35% and answering "not flagged" every time on 83.37%; of the accounts it flags,
79.59% are flagged in the data (dense: 72.79%), and it finds 63.51% of the flagged ones (dense:
57.46%); F1 0.7065 against 0.6422. The native build agrees with the pure-Python reference on all
7,054 rows and on every tree's output in 1,000 traces; the forest on the EVM agrees on the 20 rows
and the full trace checked there. Running the whole forest on-chain costs 1,301,202 gas; claiming
and finalising an answer costs 251,287 (19.3% of that), and the dearest dispute 118,880 (9.1%).
**On this data the dense network was too small for the dispute protocol to pay (its honest path
cost 181.8% of a whole run); the better model is also the one where it does.**

## The model

| | |
|---|---|
| Data, split, thresholds, test rows | `examples/address-risk`, unchanged: `features.py`, `features.json`, the 7,054 rows of its `out/inputs.bin` and `out/labels.bin` (`check.sh` compares them byte for byte) |
| Trainer | `train.py`: gradient boosting written out in NumPy (no scikit-learn or LightGBM), logistic loss, complete trees grown level by level on the 128 input levels, rule "x[feature] <= threshold goes left", second-order leaf values, learning rate 0.1, L2 1.0; no randomness |
| Selection | depth 4, 5, 6; 100, 200, 300 trees; class weight 1.0, 1.5, 2.0, 3.0 (36 candidates), each quantised and scored as integers on the **validation** rows; the best integer F1 won: depth 6, 300 trees, weight 1.5. The test rows were scored once, after the choice |
| Integer form | leaves as int16 with 14 fractional bits, one base score; the class is 1 when base + sum of the 300 leaves > 0 (ties to class 0) |

| Measure, 7,054 test rows | Forest (integer, the one the contracts run) | Dense 14-32-16-2 (integer) | Majority baseline |
|---|---|---|---|
| Accuracy | 91.22% | 89.35% | 83.37% |
| Precision | 79.59% | 72.79% | |
| Recall | 63.51% | 57.46% | |
| F1 | 0.7065 | 0.6422 | |

## Run it

```
bash examples/address-risk-trees/check.sh        # needs Fe 26.5.1, Foundry, Python 3 (standard library)
```

`check.sh` uses only what is committed. To rebuild the committed files from the data set (NumPy;
the download and its checks are the dense example's `prepare.py`, which also needs pyarrow; keep the
data directory outside the repository and run the scripts that read it with `-I`):

```
python -I examples/address-risk/prepare.py --data DIR          # downloads, checks the SHA-256, writes DIR/onchain.npz
python -I examples/address-risk-trees/train.py --data DIR      # model/address-risk-trees-300x6.json
python -I examples/address-risk-trees/export.py                # out/: model.json, inputs.bin, labels.bin, pred.bin, trace.jsonl
bash tools/gen_trees_workspace.sh examples/address-risk-trees/out/model.json examples/address-risk-trees/out examples/address-risk-trees 8
```

`export.py` and the reference (`tools/trees_ref.py`) are pure Python, so CI re-runs the reference on
every test row without NumPy. Training is deterministic for one machine; another CPU or NumPy build
may round differently and give a slightly different forest. The committed model is the one every
figure here belongs to.

| File | What |
|---|---|
| `train.py`, `model/` | the trainer and the trained forest with its training record (every candidate's validation scores) |
| `export.py`, `out/` | the reference vectors and the test metrics, from the pure-Python reference |
| `ingots/model`, `arbiter`, `ensemble`, `cli` | generated by `tools/gen_trees_workspace.sh`, never edited |
| `ingots/consumer` | `RiskGate` against the tree arbiter, hand-written, 7 tests |
| `gate_anvil.sh` | the use on a local chain: claim, finalize, score, enter, and every refusal |
| `check.sh`, `results.py`, `runs/`, `RESULTS.md` | the checks, their records, and the report made from them |

## Limits

- **Everything in the dense example's Limits applies unchanged**: the arbiter proves a computation,
  not a verdict; nobody checks that the 14 bytes belong to the account; the input must be public;
  the data is old (to February 2021) and its labels noisy; its 16.3% scam rate is not the chain's,
  so precision on real traffic would be lower (not measured); a gate like this refuses real people
  (here 191 of the 936 test accounts the forest flags are not flagged in the data) and needs an
  appeal path.
- **The answer is late.** A claim is final only after the challenge window. A contract that needs
  the answer in the same transaction pays 1,301,202 gas to `Ensemble`, which calls the 5 contracts
  that hold the trees (76,800 bytes of tree words do not fit one contract).
- **A single dispute costs more gas than the dense network's** (118,880 against 101,727, the
  dearest of each): the challenge carries the tree's 8 words, a 9-sibling proof and the 19 committed
  output words. It is the share of a whole run that is small (9.1% against 65.7%).
- **Bigger to commit to.** A claim carries 300 tree outputs (19 words, 608 bytes), against two
  logits for the dense network; the event carries them too.
- **Evidence for the tree arbiter** is its generated Fe contract tests and the anvil scripts. The
  repository's Foundry fuzz suite and mutation run cover the dense arbiter only.
- **One family of trees.** Complete trees of one depth, binary or `t % classes` multi-class targets,
  int16 leaves. A random forest's vote fits as leaf values of 0 or 1 per class tree; a forest of
  mixed depths is padded to the deepest. Neither was built here.
